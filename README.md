# Кадр — интеллектуальная подготовка фотографий

Статическое React-приложение для подготовки одной или нескольких фотографий под каталог точных размеров. DeepSeek Vision один раз анализирует каждую фотографию и возвращает план кадрирования и умеренной коррекции для всех выбранных форматов. Пиксели обрабатываются локально в браузере; готовые файлы можно скачать отдельно, одним ZIP с `manifest.json` или отправить временную ссылку на ZIP по почте.

## Быстрый старт

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Откройте адрес Vite, введите собственный DeepSeek API key, добавьте фотографии и выберите форматы.

Проверки:

```bash
npm run format
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
```

E2E-тест включает `VITE_MOCK_DEEPSEEK=true` только для локального dev-сервера Playwright и не обращается к DeepSeek.

## Архитектура и поток данных

1. Браузер читает EXIF orientation, декодирует файл и нормализует ориентацию на Canvas.
2. Уменьшенная JPEG-копия (не более 1600 px по длинной стороне), размеры ориентированного исходника, prompts и параметры выбранных форматов отправляются напрямую в официальный DeepSeek Responses API. Endpoint разрешает CORS для опубликованного GitHub Pages origin; промежуточный Cloudflare Worker не используется.
3. На одну исходную фотографию выполняется один основной vision-запрос для всех форматов. При невалидной инструкции разрешён ровно один repair-запрос; временные `429`/`5xx` повторяются с exponential backoff и jitter. Одновременно анализируются не более двух фотографий.
4. Ответ запрашивается через JSON Schema (`text.format`, `type: "json_schema"`), затем повторно проверяется Zod и семантическими правилами в браузере. Помимо crop модель обязана вернуть визуальный поворот исходника на `0`, `90`, `180` или `270` градусов; координаты проверяются относительно уже повёрнутых размеров.
5. Оригинал повторно декодируется локально. При необходимости Canvas сначала исправляет визуальную ориентацию, затем выполняются crop, ресемплинг `pica`, детерминированная цветокоррекция и кодирование. Исходный файл не загружается никуда ещё.
6. JPEG quality подбирается бинарным поиском по фактическому размеру Blob во всём допустимом диапазоне `0–1`: выбирается максимальное качество, укладывающееся в лимит. Если минимального quality недостаточно, дополнительный локальный fallback через `pica` находит максимальный уровень внутренней детализации, возвращает изображение к точным целевым размерам и повторяет поиск quality. PNG остаётся lossless: если лимит недостижим, это явно отмечается. Габариты, MIME и повторное декодирование проверяются до показа результата.
7. ZIP содержит только результаты, уложившиеся в лимит, по папке на исходник. `manifest.json` не содержит ключ, исходные изображения, пользовательские prompts или полный ответ модели.
8. При отправке по почте ZIP загружается по короткоживущей подписанной ссылке в закрытый Yandex Object Storage. Cloud Function после проверки SmartCaptcha отправляет через Yandex SMTP ссылку, действующую 24 часа. При обычном скачивании ZIP никуда не загружается.

Код разделён на каталог данных (`src/data`), конфигурацию модели и системный prompt (`src/config`), валидацию/DeepSeek/Canvas/очередь/ZIP (`src/lib`) и UI (`src/components`, `src/App.tsx`). Вызов API сделан через стандартный `fetch`, чтобы не включать серверный SDK и его окружение в статический bundle. Синтаксис сверялся с официальной документацией DeepSeek: [Vision](https://api-docs.deepseek.com/guides/vision/), [Responses API](https://api-docs.deepseek.com/guides/responses_api/) и [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/).

## Безопасность BYOK

API key существует только в React state текущей вкладки. Приложение не записывает его в `localStorage`, `sessionStorage`, IndexedDB, URL, ZIP, логи или telemetry. Браузер отправляет ключ непосредственно официальному DeepSeek API в заголовке `Authorization`.

Полностью статический BYOK-интерфейс всё равно не является секретным хранилищем: выполняющийся на странице JavaScript видит введённый ключ. Пользуйтесь только доверенной опубликованной сборкой. В DeepSeek создайте отдельный API key для этого инструмента, поддерживайте небольшой баланс и отзывайте ключ, когда он больше не нужен. Не используйте личный основной ключ.

BYOK-ключ всё ещё доступен JavaScript доверенной страницы и передаётся DeepSeek во время запроса. Для многопользовательской production-версии с общим ключом нужны аутентификация, rate limits, квоты и секрет только на серверной стороне. Общий секрет нельзя раздавать браузерам.

## Форматы

Встроенный каталог находится в [`src/data/default-formats.ts`](src/data/default-formats.ts) и сформирован по `docs/formats.md`. Галерея «АФИША ГОРОДА РУ», где источник допускает JPEG или PNG, по умолчанию использует JPEG: для неё, как и для остальных основных пресетов, действует лимит 200 КБ. При необходимости её можно продублировать в UI и сменить тип на PNG. Требование 300 dpi для галереи Kassir отражено в prompt, но Canvas гарантирует пиксельные размеры, а не печатные DPI-метаданные.

Пользовательские форматы сохраняются в `localStorage`; доступны создание, редактирование, дублирование, удаление, JSON-импорт/экспорт и сброс. Поддерживаемые поля шаблона имени: `{sourceBase}`, `{formatName}`, `{formatSlug}`, `{width}`, `{height}`, `{ext}`. Запрещённые файловые символы очищаются, коллизии получают детерминированные суффиксы.

## Модель и prompt

Профили централизованы в [`src/config/models.ts`](src/config/models.ts):

- `deepseek-flash` (`DeepSeek-V4.1-Flash`) — используется приложением: поддерживает Vision, Responses API и структурированный JSON;
- `deepseek-v4-pro` — предназначен для более сложных текстовых задач, но не поддерживает изображения, поэтому для этого pipeline не предлагается.

Для надёжного структурированного ответа thinking отключён через `reasoning.effort: "none"`: лимит вывода целиком остаётся финальному JSON, а композиционные требования подробно заданы системным prompt. При пустом или невалидном ответе выполняется один уточняющий повтор. Системный prompt расположен в [`src/config/system-prompt.ts`](src/config/system-prompt.ts). ID модели централизован и не дублируется в UI и API-клиенте.

## Ограничения обработки

- Поддерживаются JPEG, PNG и WebP до 30 МБ и до 50 мегапикселей. Это предохраняет вкладку от предсказуемого дефицита памяти.
- Финальные форматы — JPEG или PNG. Цветокоррекция аппроксимирует экспозицию, контраст, насыщенность, температуру, highlights и shadows; sharpening выполняет `pica`.
- Canvas ориентируется на sRGB, но точное управление ICC-профилями и результат декодирования могут немного различаться между браузерами и ОС. При записи браузер обычно не сохраняет исходные EXIF/ICC metadata.
- Upscale разрешён ради точного размера, но помечается предупреждением.
- PNG кодируется lossless без ложной надежды на аргумент `quality`. Palette quantization в MVP не применяется.
- Браузер не удаляет и не дорисовывает текст, логотипы или объекты. Модель может только подобрать crop и предупредить о конфликте.
- Приложение обращается напрямую к `https://api.deepseek.com/responses`. Сетевые ошибки отображаются без вывода ключа или тела запроса.

## GitHub Pages

Workflow [`.github/workflows/pages.yml`](.github/workflows/pages.yml) запускает форматирование, lint, typecheck, unit/integration tests и production build, после чего публикует `dist`. Для project pages он передаёт Vite базовый путь `/<repository-name>/`; локально используется `/`.

В репозитории GitHub откройте **Settings → Pages → Source** и выберите **GitHub Actions**. Затем отправьте изменения в ветку `main`. DeepSeek API key и серверные Yandex Cloud secrets в GitHub не добавляются.

Для включения кнопки отправки ZIP workflow читает две публичные repository variables: `VITE_EMAIL_API_URL` и `VITE_SMARTCAPTCHA_SITE_KEY`. Полная настройка Object Storage, Yandex SMTP, SmartCaptcha и Cloud Function описана в [`docs/yandex-email-setup.md`](docs/yandex-email-setup.md).

Приложение не использует client routing, поэтому обновление страницы и размещение в подпути GitHub Pages не требуют SPA fallback.

# Отправка ZIP через Yandex Cloud

Приложение не передаёт секреты в GitHub Pages. Браузер получает от Cloud Function короткоживущую подписанную ссылку, загружает ZIP непосредственно в закрытый Object Storage, после чего функция отправляет через SMTP обычного ящика Yandex письмо со ссылкой на скачивание. Ссылка действует 24 часа. SmartCaptcha защищает публичную функцию от массовой отправки.

## 1. Создать сервисный аккаунт и бакет

1. В нужном каталоге Yandex Cloud откройте **Identity and Access Management → Сервисные аккаунты**.
2. Создайте аккаунт `photo-mailer`.
3. Откройте **Object Storage** и создайте бакет с глобально уникальным именем, например `photo-smart-formatter-mail-<суффикс>`.
4. Оставьте выключенными публичное чтение объектов, публичный список объектов и публичное чтение настроек.
5. В бакете откройте **Безопасность → Привязки доступа**, добавьте `photo-mailer` с ролью `storage.editor`.
   Роль `storage.editor` нужна функции для проверки архива, создания блокировки от повторной отправки и удаления блокировки после временной ошибки SMTP. Ограничьте эту роль конкретным бакетом.

## 2. Настроить CORS и автоматическое удаление

В бакете откройте **Безопасность → CORS** и добавьте правило:

- Allowed Origins: `https://toshafree.github.io`, `http://localhost:5173`, `http://127.0.0.1:5173`;
- Allowed Methods: `PUT`;
- Allowed Headers: `Content-Type`, `If-None-Match`;
- Expose Headers: `ETag`;
- MaxAgeSeconds: `3600`.

Если используется другой домен, добавьте его точный origin без пути. Готовый вариант для AWS CLI находится в [`yandex-function/cors.example.json`](../yandex-function/cors.example.json).

Затем откройте **Настройки → Жизненный цикл** и создайте включённое правило без префикса:

- действие: `Expiration`;
- срок: `1 день`.

Object Storage применяет lifecycle по расписанию, поэтому ссылка перестанет работать через 24 часа, а физическое удаление может произойти позже во время очередного цикла очистки. JSON-пример находится в [`yandex-function/lifecycle.example.json`](../yandex-function/lifecycle.example.json).

## 3. Настроить ящик Yandex для SMTP

1. В настройках Yandex Почты откройте **Почтовые программы**.
2. Включите доступ почтовых программ и использование паролей приложений/OAuth-токенов.
3. В Yandex ID создайте отдельный пароль приложения типа **Почта**.
4. Сохраните полный адрес ящика: он понадобится как `SMTP_USER`.

Функция подключается к `smtp.yandex.ru` по SSL на порту `465`. В Lockbox сохраняйте именно пароль приложения, а не основной пароль от аккаунта.

## 4. Создать SmartCaptcha

1. Откройте **SmartCaptcha** и создайте CAPTCHA.
2. В разрешённые сайты добавьте `toshafree.github.io`. Для локальной проверки при необходимости добавьте `localhost`.
3. Сохраните оба значения:
   - клиентский ключ `ysc1_…` — публичный, он пойдёт в GitHub Variable;
   - серверный ключ `ysc2_…` — секретный, он пойдёт в Lockbox.

## 5. Создать статический ключ и Lockbox

1. В сервисном аккаунте `photo-mailer` создайте **статический ключ доступа**.
2. Сразу сохраните `Access key ID` и `Secret key`: секретное значение повторно не показывается.
3. Сгенерируйте случайный ключ подписи, например локально:

   ```bash
   openssl rand -hex 32
   ```

4. Создайте секрет Lockbox `photo-mailer-secrets` с четырьмя парами:
   - `AWS_SECRET_ACCESS_KEY` — Secret key статического ключа;
   - `SMTP_PASSWORD` — пароль приложения Yandex Почты;
   - `SMARTCAPTCHA_SERVER_KEY` — серверный ключ SmartCaptcha;
   - `SESSION_SECRET` — результат команды выше.
5. На этот секрет выдайте аккаунту `photo-mailer` роль `lockbox.payloadViewer`.

Секреты не добавляйте в репозиторий, GitHub Variables или клиентские `.env`-файлы.

## 6. Создать Cloud Function

1. Откройте **Cloud Functions** и создайте функцию `photo-mailer`.
2. Создайте версию со следующими параметрами:
   - runtime: **Node.js 22**;
   - entrypoint: `index.handler`;
   - timeout: `30 секунд`;
   - память: `256 МБ`;
   - сервисный аккаунт: `photo-mailer`.
3. Загрузите в редактор содержимое каталога [`yandex-function`](../yandex-function): `index.js`, `package.json` и `package-lock.json`. Файлы `*.example.json` в функцию загружать необязательно.
4. Добавьте обычные переменные окружения:

   | Переменная             | Значение                                                                  |
   | ---------------------- | ------------------------------------------------------------------------- |
   | `AWS_ACCESS_KEY_ID`    | ID статического ключа                                                     |
   | `BUCKET_NAME`          | имя созданного бакета                                                     |
   | `SMTP_USER`            | полный адрес ящика Yandex                                                 |
   | `SMTP_HOST`            | `smtp.yandex.ru`                                                          |
   | `SMTP_PORT`            | `465`                                                                     |
   | `EMAIL_SENDER_NAME`    | имя отправителя, например `Фотоформат`                                    |
   | `ALLOWED_ORIGINS`      | `https://toshafree.github.io,http://localhost:5173,http://127.0.0.1:5173` |
   | `DOWNLOAD_TTL_SECONDS` | `86400`                                                                   |
   | `MAX_ARCHIVE_BYTES`    | `157286400`                                                               |

5. В блоке **Секреты Lockbox** подключите ключи секрета к одноимённым переменным окружения:
   - `AWS_SECRET_ACCESS_KEY`;
   - `SMTP_PASSWORD`;
   - `SMARTCAPTCHA_SERVER_KEY`;
   - `SESSION_SECRET`.
6. Сделайте функцию публичной. Публичный вызов безопасен только вместе со SmartCaptcha; CORS сам по себе не является защитой.
7. Скопируйте URL функции вида `https://functions.yandexcloud.net/<function-id>`.

Статический ключ используется только для S3-совместимого API Object Storage. SMTP-пароль берётся отдельно из Lockbox. Код не выводит email, токены CAPTCHA, подписанные ссылки или секреты в логи.

## 7. Добавить публичные переменные в GitHub

В репозитории откройте **Settings → Secrets and variables → Actions → Variables** и создайте:

| GitHub Variable              | Значение                 |
| ---------------------------- | ------------------------ |
| `VITE_EMAIL_API_URL`         | URL Cloud Function       |
| `VITE_SMARTCAPTCHA_SITE_KEY` | клиентский ключ `ysc1_…` |

Это публичные значения, поэтому используются именно Variables, а не Secrets. Workflow передаст их Vite во время production build. После сохранения переменных повторно запустите workflow **Test and deploy to GitHub Pages** или отправьте новый коммит в `main`.

Для локальной проверки создайте `.env.local` по образцу [`.env.example`](../.env.example). `.env.local` не коммитьте.

## 8. Проверить

1. Подготовьте хотя бы один результат.
2. В разделе результатов нажмите **Отправить ZIP по почте**.
3. Введите доступный email и пройдите SmartCaptcha.
4. Убедитесь, что письмо пришло, ссылка скачивает `prepared-photos.zip`, а бакет содержит объект в `archives/` и блокировку в `locks/`.
5. Проверьте папку **Отправленные** в Yandex Почте.

Если кнопка не показывается, production build не получил одну из двух переменных `VITE_*`. Если загрузка ZIP блокируется браузером, сначала перепроверьте CORS бакета. Если загрузка проходит, но письмо не приходит, смотрите логи Cloud Function и проверяйте пароль приложения и настройки доступа почтовых программ в Yandex Почте.
